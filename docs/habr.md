# GPT в Claude Code: модели OpenAI, привычный интерфейс

Мне нравятся модели OpenAI, но работать удобнее в Claude Code. Поэтому я попросил агента в Codex поселить GPT в Claude Code и его расширении для VS Code. Причём через мою подписку, без отдельного API-ключа.

Получился `claude-gpt`: открываю привычное расширение, выбираю GPT и работаю с проектом. Код, тесты, установщик и исправления целиком написал ИИ-агент. Я отвечал за пожелания и регулярную поставку скриншотов «опять упало». Разделение труда меня устроило.

## Зачем

За пару месяцев я привык к Claude Code: чат рядом с кодом, просмотр диффов, запуск команд, работа с файлами. Особенно нравится организация проектов. У каждого своя история чатов, в которой легко найти нужный разговор. Открываю проект и вижу его задачи, а не ищу их в общей ленте, как у меня было в Codex.

Это и стало главной причиной затеи. Хотелось оставить знакомое окружение, но выбирать модели OpenAI. Подписка уже была, привычки тоже. Менять привычки оказалось сложнее, чем заказать мост между двумя продуктами.

Для меня было важно, чтобы всё работало и в терминале, и в VS Code, а перед открытием расширения не приходилось ничего запускать вручную.

## Как работает

`claude-gpt` написан на Rust и служит переводчиком между Claude Code и OpenAI:

```text
Claude Code / VS Code
        ↕ Messages API
    claude-gpt
        ↕ Responses
      OpenAI
```

Claude Code по-прежнему ведёт историю, читает файлы и выполняет инструменты. Мост переводит сообщения и результаты инструментов в формат OpenAI, отправляет их выбранной GPT-модели и переводит ответ обратно. Поддерживаются потоковые ответы и обычный JSON.

Для доступа используются библиотеки Codex и существующая авторизация через ChatGPT. Запросы расходуют доступную квоту аккаунта. Вход по API-ключу мост отвергает.

Расширение подключается через настройку `claudeCode.claudeProcessWrapper`. Она позволяет запускать Claude Code через нашу обёртку. Переписывать бинарники Claude Code или расширения не понадобилось.

При запуске обёртка поднимает HTTP-шлюз на localhost, выбирает случайный порт и создаёт токен для локальных запросов. При обычном завершении закрывает шлюз. Всё происходит автоматически: постоянного демона и ручного запуска сервера нет.

## Что получилось

В списке моделей видны названия GPT. Каталог загружается через Codex при запуске, поэтому новые совместимые модели могут появляться автоматически. Оттуда же берутся размеры окон и поддерживаемые уровни effort.

По умолчанию я выбрал Terra. Для небольших задач добавили Spark, если он доступен аккаунту. Команда `/codex-usage` показывает оставшуюся квоту и время сброса, включая отдельные лимиты Spark, когда сервис их возвращает.

Продолжение чатов идёт через механизмы Claude Code. Мост учитывает выбранное окно контекста, хотя локальная оценка токенов приблизительная. Ещё добавили экспериментальную генерацию изображений через MCP: картинки сохраняются в проект, агент получает путь к файлу.

Без приключений не обошлось. Первые версии спотыкались о картинки внутри результатов инструментов, путали окно возобновлённой сессии и отвергали запросы без streaming. Эти случаи агент исправлял по мере того, как я находил их в работе. Полную хронику ошибок здесь опущу: я её уже прочитал в своём редакторе.

Пока это личный эксперимент для macOS Apple Silicon с закреплёнными версиями Claude Code, расширения и Codex. Обновления могут потребовать доработок, а совместимость со всеми возможностями Claude Code я не обещаю. Точные требования, установка и ограничения есть в README.

Исходники открыл под MIT. Если вам тоже удобнее работать в Claude Code, а модели хочется выбирать отдельно, можно посмотреть, как устроен мост, и попробовать на совместимой конфигурации.
