# Мне нравится Claude Code, но я хочу GPT: как ИИ-агент поселил модели OpenAI в привычном окружении

Последние пару месяцев я работал с Claude Code. Привык к его терминалу, а особенно — к расширению для VS Code. Открываешь проект, рядом живёт чат, агент читает файлы, предлагает изменения, запускает команды. Там же видны диффы и результаты работы. Мне удобно именно так.

При этом мне нравятся модели OpenAI. И в какой-то момент захотелось довольно простой вещи: оставить окружение, к которому я привык, но выбирать внутри него GPT.

Я написал агенту в Codex: «Твоя задача — подружиться с claude-code».

Получился небольшой проект на Rust — `claude-gpt`. Он запускает Claude Code с локальным мостом к моделям, доступным через мою авторизацию Codex/ChatGPT. Работает и с CLI, и с расширением VS Code. В этой статье расскажу, чего я хотел как пользователь, что в итоге получилось и почему между «модель ответила» и «этим удобно пользоваться» обнаружилось столько мелочей.

Сразу про авторство: код, тесты, установщик и исправления написал ИИ-агент в Codex. Я формулировал требования, выбирал компромиссы, пользовался результатом и приносил скриншоты очередной ошибки. Дальше будет рассказ с моей, пользовательской стороны. Технические детали я сверил с тем, что агент действительно оставил в исходниках.

## Хотел поменять модель, а не свои привычки

Можно спросить: если нравятся модели OpenAI, почему просто не пользоваться Codex?

Я им и пользовался — в нём же появился этот проект. Но рабочее окружение тоже имеет значение. Мне хотелось продолжать задачи в знакомом Claude Code и видеть результат в привычном расширении. Не переносить разговор между приложениями, не заново объяснять проект, не менять привычный способ просмотра изменений ради другой модели.

Мои требования постепенно сложились в довольно конкретный список:

- Использовать именно подписку через вход Codex/ChatGPT.
- Сохранить CLI и расширение Claude Code для VS Code.
- Видеть названия GPT-моделей в выборе моделей.
- Продолжать существующие чаты и учитывать размер контекста.
- Не запускать вручную отдельный сервер перед работой.
- Видеть оставшуюся квоту и время её сброса.

Сначала я вообще не собирался ничего распространять. Нужен был инструмент для моего Mac. Ради него я был готов закрепить версии и даже согласился на патчи. Это заметно сузило задачу: вместо универсального решения для всех платформ можно было довести конкретную связку.

В итоге переписывать бинарники Claude Code не понадобилось. Обёртка подключилась через доступные в установленной версии настройки. Но зависимость от конкретных версий всё равно осталась — об этом ниже.

## Что мы на самом деле запустили

На пользовательском уровне всё выглядит просто: открываю Claude Code, выбираю GPT и работаю. Внутри между интерфейсом и моделью появился переводчик.

```text
Claude Code CLI или расширение VS Code
                 ↕
       Messages API: JSON / SSE
                 ↕
             claude-gpt
                 ↕
       Responses через Codex
                 ↕
            модели OpenAI
```

Claude Code продолжает вести разговор и выполнять инструменты. `claude-gpt` принимает модельные запросы, переводит их в формат OpenAI и переводит ответы обратно. Системные инструкции, сообщения и результаты инструментов, попавшие в запрос, уходят к выбранной модели OpenAI.

Важная поправка к моему первоначальному «без сервера»: временный HTTP-сервер здесь есть. Он слушает `127.0.0.1` на случайном порту и живёт внутри процесса обёртки. При запуске создаётся случайный токен, настройки передаются дочернему Claude Code. При обычном завершении обёртка закрывает и шлюз.

Для меня решающим было то, что им не надо отдельно управлять. Расширение запускает обёртку через настройку `claudeCode.claudeProcessWrapper`. Открыл VS Code — нужный процесс поднимается сам. После установки или обновления самого моста нужно перезагрузить окно расширения.

Есть и ещё один процесс: для генерации изображений тот же бинарник умеет запускаться как stdio MCP-сервер. Это тоже автоматически запускаемый компонент, а не постоянно работающий демон.

Подписочная авторизация используется через библиотеки из исходников Codex, закреплённые на конкретном коммите. В мосте проверяется тип входа: API-key auth он отвергает. Это было моим прямым требованием.

У OpenAI [вход через ChatGPT и вход по API-ключу описаны как разные способы доступа](https://learn.chatgpt.com/docs/auth). Наш проект использует первый, но сам мост к Claude Code — сторонний эксперимент. Наличие подписки не означает, что у каждого аккаунта будет одинаковый каталог моделей или что эта интеграция официально поддерживается поставщиками.

## Почему нельзя просто переименовать Sonnet в GPT

Я хотел видеть нормальный список моделей. Если выбрал Terra — значит Terra, если Spark — значит Spark. Прятать выбор за названиями Claude было бы неудобно, особенно когда разные модели по-разному расходуют квоту.

Мост получает каталог при запуске и оставляет подходящие GPT-модели. Из него же берёт поддерживаемые уровни effort и размеры окон. Совместимая новая модель может появиться в списке без отдельной правки исходников. При проблемах с получением каталога предусмотрен кэш.

По умолчанию я попросил поставить Terra. Самую тяжёлую модель не хотелось случайно запускать на мелкой задаче просто потому, что она оказалась первой в списке. Spark добавили как вариант для небольших поручений; его отдельные лимиты тоже нужно было видеть.

С effort пришлось договориться о переводе. В интерфейсе Claude Code свой набор уровней, у модели — свой. Наш `max` означает самый высокий доступный семантический уровень; конкретное значение, которое уходит в запрос, определяется поддержкой модели и логикой моста. Нельзя считать, что одинаковая надпись в двух приложениях гарантирует одинаковое поведение.

С контекстом оказалось ещё интереснее. Во время разработки каталог для Terra содержал варианты на 272K и 872K. Это данные нашей конфигурации на тот момент, а не обещание такого окна всем владельцам определённой подписки.

При одном из продолжений интерфейс показывал 872K, а в истории сессии фактически сохранялся идентификатор варианта на 272K. В результате запрос остановился на такой ошибке:

```text
estimated 258726 input tokens exceeds the usable model limit of 258400
```

Человеку перед экраном это выглядит нелепо: внизу почти миллион, ошибка говорит о четверти миллиона.

После этой истории агент добавил переход на расширенный вариант той же модели, если стандартное окно уже не вмещает запрос, а расширенное есть в каталоге и подходит по оценке длины. В противном случае мост возвращает ошибку. Сам он не вырезает куски разговора; compact остаётся задачей Claude Code.

Это полезная страховка для нашей сессии, но не универсальное решение проблемы контекста. Локальный подсчёт приблизительный, для картинок используется фиксированная оценка. Большой контекст может означать больший расход квоты. Обещать «любую историю любой длины» после такого опыта я бы точно не стал.

## «Почти работает» — самая длинная часть

Первые ответы GPT в Claude Code выглядели как победа. Потом я начал делать обычные задачи и отправлять агенту сообщения вроде «что-то упало».

Оказалось, что совместимость проверяется не первым текстовым ответом. Она проверяется следующим запросом после инструмента, чтением картинки и продолжением вчерашнего чата.

### Команда usage, которую модель воспринимала как разговор

Штатный usage в Claude Code не показывал нужную мне картину по Codex. Агент добавил `/codex-usage`, но в расширении команда сначала не давала ожидаемого результата: модель отвечала текстом, иногда фактически переписывая последнее сообщение.

Проблема была в обработке команды. Её нельзя просто отправить GPT с надеждой, что та поймёт, как показать квоту.

Теперь мост распознаёт команду, получает usage и возвращает готовый результат без обращения к модели. В нём есть доступные окна лимитов, использованная и оставшаяся доля, время сброса в UTC. Данные кэшируются на минуту.

После того как это заработало, я попросил оформить результат таблицей. На фоне протокольных ошибок просьба почти смешная, но именно такие вещи и определяют, удобно ли инструментом пользоваться каждый день.

### Генерация картинки не заканчивается сохранением PNG

Следующая просьба была вполне ожидаемой: раз GPT уже внутри, пусть ещё и генерирует изображения.

Агент добавил MCP-инструмент `imagegen`. Результат сохраняется в проект, в ответ возвращается путь. Генерация у меня заработала. А затем модель решила посмотреть, что получилось, и прочитала несколько изображений.

Тут последовательно обнаружились разные проблемы. Сначала переводчик не понимал блок `tool_reference`, возвращённый поиском инструментов. Затем — картинку внутри результата инструмента. Отдельно всплыл размер HTTP-запроса: накопившиеся вложения способны упереться в лимит тела запроса независимо от количества токенов.

В перевод добавили обработку этих блоков; локальный предел размера запроса выставили в 32 MiB. Однако автоматического уменьшения картинок и очистки старых вложений в текущем коде нет. Поэтому я считаю генерацию изображений экспериментальной возможностью, а не поводом обещать бесконечный мультимодальный чат.

Для меня здесь был показательный момент: «модель умеет видеть» и «наше окружение правильно передаёт ей результат чтения файла» — два разных условия, и нужны оба.

### Запрос внезапно оказался не потоковым

Ещё одна остановка случилась после запуска тестов в Bash:

```text
Claude Code gateway requires streaming requests
```

Это ограничение было написано в нашем мосте. В первой реализации он принимал только потоковые запросы. Но Claude Code прислал запрос, для которого ожидался обычный JSON-ответ.

Агент добавил сборку такого ответа из тех же переведённых событий: текст, вызовы инструментов, причина остановки и usage складываются в итоговый объект сообщения. Для потокового режима остался SSE.

В регрессионном тесте сначала воспроизвели 400, затем проверили получение JSON с текстом и tool call. Так ошибка из моего скриншота превратилась в проверяемый контракт.

## Что для меня сделало агентную разработку полезной

В этой работе мне не пришлось самому разбираться во всех Rust-типах и писать переводчик протокола. Но роль пользователя оказалась довольно активной.

Я уточнял то, что легко потерять за технической задачей: «именно через подписку», «а в расширении тоже?», «перед запуском ничего руками?», «можно продолжить этот чат?», «поставь Terra по умолчанию». Агент переводил это в код. Я возвращался в рабочий проект — и находил следующий случай, который не покрыл первый вариант решения.

При этом зелёные тесты не избавили меня от ошибок в реальном чате. Они проверяли уже известные нам ситуации. Когда появлялся новый формат результата инструмента или другой режим запроса, требовалась новая проверка и доработка.

Именно так я и воспринимаю этот проект: агент сделал реализацию, а обычная работа дала ему обратную связь, которую не заменил бы один демонстрационный запрос «ответь OK».

## Насколько это готово для чужого Mac

Исходники я решил открыть, но не хочу выдавать личный эксперимент за бесшовный продукт.

Текущая версия рассчитана на macOS Apple Silicon и закреплённую комбинацию: Claude Code CLI 2.1.258, расширение и embedded CLI 2.1.260, Codex 0.153.1. Проверяются версии и хэши файлов. Пути к приложениям тоже пока привязаны к конкретной раскладке установок.

Такой подход даёт понятное поведение после локального обновления: если файлы перестали соответствовать проверенной конфигурации, мост откажется запускаться. Это лучше описывает его устойчивость, чем обещание «никогда не сломается». Серверную сторону OpenAI закреплением локальных версий всё равно не заморозить.

Есть установщик с резервной копией настройки VS Code, команды `repair`, `uninstall` и `doctor`. Обычный `doctor` проверяет окружение и каталог, не вызывая модель. Вариант `doctor --live` делает минимальный модельный запрос и расходует квоту.

В репозитории есть контрактные тесты перевода запросов и ответов, выбора моделей, установки и отката. Live-тесты выделены отдельно и по умолчанию пропускаются: им нужны приложения и действующая подписка. Успешный прогон локальных тестов не означает, что проверены все возможности Claude Code на всех аккаунтах.

И ещё несколько границ: это не полная реализация Messages API; некоторые параметры, в том числе `max_tokens` и `stop_sequences`, пока не переводятся в исходящий запрос. Автокомпакт длинных разговоров требует дальнейшей проверки. Наличие инструмента WebSearch в интерфейсе само по себе не означает, что мост реализует поиск OpenAI. Эти ограничения указаны и в README.

## Что я в итоге получил

Я хотел остаться в удобном мне Claude Code и его расширении VS Code, но получить выбор GPT-моделей через свою подписочную авторизацию. Для моей закреплённой конфигурации такой мост появился. Ради него не приходится вручную поднимать сервер при каждом открытии редактора.

Больше всего в этой истории мне нравится возможность выбирать отдельно модель и привычное рабочее окружение. Теперь я вижу и цену этой свободы: кто-то должен поддерживать перевод протоколов, обработку инструментов и несовпадающие ожидания двух продуктов. В нашем случае этим кем-то оказался ИИ-агент, которому я время от времени присылал очередное «новая ошибка».

Публикую исходники под MIT: с тестами, установщиком, описанием ограничений и без чужих бинарников или моей авторизации. Если вам тоже нравится окружение Claude Code, а модели хочется выбирать отдельно, возможно, этот эксперимент окажется полезной отправной точкой.
